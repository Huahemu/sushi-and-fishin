# How to Fish Portable — 移植指南

这是独立的 Unity 6 项目，核心命名空间为 `HowToFish`。源素材来自用户提供的 How.to.Fish-v1.1.1 文件夹。导出的核心包不依赖寿司项目，不修改目标工程的场景、ProjectSettings、输入设置或 XR 配置。

## 导入

1. 在目标工程导入 `HowToFishCore.unitypackage`。建议 Unity 6000.6 / URP 17.6，图鉴界面需要 Unity UI（uGUI）；已有同版本 URP 的项目可直接使用材质。其他渲染管线需要重新绑定调色板材质。
2. 将 `Assets/HowToFish/Prefabs/FishingSystem.prefab` 拖入场景。它包含鱼竿、五把枪、物理鱼饵和鱼线、捕获配置与收获存储；不包含演示地面、水面、玩家或输入控制器。
3. 使用 `FishingRigAdapter.prefab`，或在自己的玩家上添加 `FishingRig`。设置 `view` 为当前玩家相机，`hands` 为左右两只 `FishingHand`，并把它们放到自己的抓握点。手上的模型会跟随抓握点和视角。
4. 将该 Rig 绑定到 `FishingModule.rig` 和 `FishCombat.rig`；也可在玩家初始化时调用 `module.BindRig(rig)`。`waterSurface` 绑定目标工程的水平海面 Transform；`zones` 定义允许垂钓的范围；`islandCenter` 设置为岛屿中心，供鱼朝海面逃跑。
5. 保留现有项目的移动 / XR 加载器。核心程序集不引用 Input System 或 XR 插件。`Demo` 文件夹的键鼠、第一人称和标准 XR 桥接只用于独立演示。

## 接输入

`FishingControls` 组件提供可绑定到 UnityEvent 的方法：`EquipRod`、`EquipWeapon(index)`、`BeginCast`、`ReleaseCast`、`SetReel(float)`、`LeftTrigger(float)`、`RightTrigger(float)`、左右抓放、换弹和存鱼。

VR 中将 `rig.Tracked` 和两只 `FishingHand.tracked` 设为 true，并让自己的 XR 跟踪驱动左右抓握点。持竿手扳机拉竿 / 松开抛出；另一手扳机或绕摇柄旋转收线。持枪手扳机开火，主按钮调用对应的 Reload 方法。原始工程没有 VR 输入，以上是移植用的 VR 适配。

```csharp
using HowToFish;
using UnityEngine;

public sealed class MyFishingBinding : MonoBehaviour {
    public FishingModule module;
    public FishingRig playerRig;
    public Transform sea;

    void Awake() {
        module.waterSurface = sea;
        module.BindRig(playerRig);
        module.KilledFish += fish => Debug.Log("击败：" + fish.definition.displayName);
        module.inventory.Changed += OnStorageChanged;
    }

    void OnStorageChanged() {
        // 也可以在这里接回自己的寿司原料、背包或任务系统。
    }
}
```

`WaterQuery` 可注入目标工程自己的水域判断：`module.WaterQuery = position => MyWater.Contains(position);`。水面高度仍由 `waterSurface` 提供。

水域判断同时用于咬钩、弹道水花和活鱼落水逃走。`zones` 或自定义 `WaterQuery` 必须覆盖鱼能落入的全部海面，包括岸边两侧与后方；自定义回调还需排除实体岸地。演示默认范围为以海面中心为原点的 180 × 180 米，移植时应匹配自己场景的海面，不能只覆盖抛竿前方。

`FishingCatch.IsAvailable` 统一排除逃走、入库、退役和禁用的鱼。落水时先标记 `Escaped` 并由 `module.ForgetCatch(fish)` 清理血条目标、鱼钩引用和待处理列表，再记录图鉴逃走次数。`FishingItem.Retire()` 及鱼的 `OnDisable` 也执行相同清理，避免外部销毁或禁用后留下血条。活鱼只因实际落水而逃走，不设计时、距离或离开视野的自动消失规则。

## 工具归还与抓取

`rig.Take(item)` 统一处理键鼠选择与工具架取物；键鼠模式先归还两手中的其他工具，避免 E 自动把另一件工具挂到另一只镜头抓握点。鱼可以留在另一只手，VR 跟踪手保留独立抓握。

`FishingItem.SetHome(parent, worldPosition, worldRotation)` 设置归还位置，位置与旋转相对 parent 保存。鱼竿与枪在初始化时绑定模块节点。`Recall()` 会先从旧手部节点移出，恢复模型局部姿态，再同步刚体；工具在架上与手中都保持运动学状态。目标工程移动整个模块后，工具仍回到模块内对应位置。

归还鱼竿使用 `module.ReturnRod()`，归还枪使用 `module.combat.ReturnGun(gun)`；它们会清理手部归属与相关动作。避免只清空 `owner` 而把 Transform 留在玩家手下。`FishingRod.ResetSteering()` 同时复位竿节弯曲、蓄力及摇轮姿态；持物刚体在模型更新后同步，避免重拾时保留旧物理朝向。

分段鱼已在预制体中校准关节连接点。原作部分 HingeJoint 使用自动连接点，其序列化 `connectedAnchor=(0,0,0)` 是占位值；导入后先恢复骨骼绑定姿态，再将关节自身锚点转换到连接刚体局部坐标，显式保存真实连接点。`PortableFishingBuilder.ConfigureCatchJoints` 在重建模型时执行同一处理。不要在已弯曲的动态姿态上重新烘焙锚点。

`FishingCatch.Awake` 为有分段关节的鱼设置 12 / 4 次位置 / 速度求解，原始角度限制、摆尾轴和蒙皮权重保持不变。拾取时先将各刚体设为运动学，再恢复保存的鱼段局部位置 / 旋转并同步刚体，避免把死亡时的折叠姿态带到手上。普通与异色共享的原生统一缩放（例如 GarDrip）保留；检查的是各骨骼蒙皮矩阵之间的一致性，不把统一缩放误判为损坏。

鱼的射击尺寸已统一烘焙到预制体根节点，基础放大 1.25 倍；若模型较小，再等比放大至两个外观都满足 0.9 米最长尺寸、0.2 米中间尺寸与 0.1 米最薄尺寸。`FishingCatch.shootingScale` 记录已应用的倍率，`PortableFishingBuilder.ConfigureShootingSize` 先移除旧倍率再重新计算，可重复执行。根节点同时带动骨骼、碰撞体与挂钩点，运行时不再叠加缩放；不要仅缩放可视网格或重复乘倍率。`FishDefinition.length` 保留原有生态参数含义，以免体型调整改变天气偏好与鱼种概率。

`FishingProfile.hookedReelSpeed=14` 为上钩后远处的收线速度；`hookedReelSlowdownDistance=4` 范围内逐渐降至 `hookedNearReelSpeed=3.5`。`hookedMinLine=0.12` 为钓获后的最短线长，空饵保留 `minLine=0.5`；`hookedReelSmooth=0.12` 控制平滑响应。只有上钩且主动收线时使用快速收线，未上钩时保留 `reelFrequency/reelStep/reelSmooth`。快速收线按物理步时间连续扣除线长，并对实际线长的平滑变化设置相同速度上限；桌面按住左键和 VR 收线共用这段逻辑。

自动脱钩只接受主体刚体的上表面接触：法线 Y 至少 0.65、接触点高于海面、主体中心至少高出接触点 0.02 米、上升速度不超过 1.5 米/秒，并通过垂直射线确认主体下方确有岸地。`FishCollisionRelay` 将碰撞来源刚体传给 `FishingCatch.Contact`；尾段擦过平台不代表主体已经落稳。原有“撞击超过 15 就脱钩”的分支已移除。`ReleaseCatch(fish, true)` 用于确认上岸后的惯性收束，手动 `ReleaseCatch(fish)` 保留原接口。

`FishDefinition.shore` 保存原生体长、逃跑 / 攻击速度、攻击概率、间隔、伤害与跳跃倍率。`ShoreAttackEligible` 限定为原生长度至少 1.5 米或稀有 / 传说物种，战斗显示尺寸 `shootingScale` 不改变资格。`shore.aggression` 根据原生体长和稀有度单调提高，控制攻击概率、速度、伤害与间隔；`shore.pursuePlayer` 让大型 / 稀有鱼在冷却时蓄力或靠近玩家，不主动找水逃跑。意外落水仍会逃走。小型普通鱼的接触伤害设为 0；其他鱼也仅在攻击跳跃期间伤人，挂钩和逃跑期间不造成伤害。可在各 FishDefinition 资产中单独调速度，不必让所有鱼用同一速度。

逃跑时按 `IsWaterAt` 查询实际海面，覆盖岸边前后左右，缓存方向并在移动一段距离后更新；不靠岛屿中心方向猜海的位置，也不持续追玩家。`PortableFishingBuilder.ConfigureShoreBehaviour` 可重新生成物种默认参数；重建流程在最终稀有度设置后也执行同一处理。没有新增逃跑倒计时或安全期。

## 数据与事件

- `FishingProfile`：五套原作拟饵偏好表、损耗概率、鱼线参数和弯竿曲线。原始等待 / 移动字段保留为来源数据；当前咬钩使用 `biteWaitMin / biteWaitMax`，不以原拟饵的速度与深度条件拒绝咬钩。
- `FishingProfile.landHopHeight / landHopTowardSpeed / landHopRestMin / landHopRestMax`：当前为 2.8 / 2.4 / 0.22 / 0.4；脱钩活鱼落地后，根据重力计算目标跳高的发射速度，并朝玩家水平位置跳，防止叠加向上冲量。目标高度 2.8 米，水平速度最多 2.4 米/秒，落地后短暂停顿再跳。所有连接鱼身使用相同发射速度。
- `FishingProfile.escapeWaterDepth`：当前为 0.15；脱钩活鱼身体中心低于水面 0.15 米且通过水域查询时，才逃走并移除。处于地形内部或水域外，不会只因高度低于海平面而消失。没有逃跑倒计时或安全期；死鱼不走该逃跑分支。
- `FishingProfile.shotForceScale / maxShotVelocityChange`：当前为 0.12 / 0.85；枪击按全鱼身统一的小幅速度变化处理，同一物理步的多颗霰弹共享击退上限，伤害仍逐颗结算。死亡不会隐藏模型或自动入库。
- `FishCombat.effects`：预制体已绑定 `FishingShotEffects` 和两份材质，导入核心包会一并带入自定义无光照着色器。128 个弹道槽、12 个粒子槽固定复用；单条弹道保留约 0.11 秒。鱼身命中与击杀使用红色血滴飞溅、约 0.55 秒的伤口滴血；每个粒子槽最多 32 滴，模拟空间为世界空间，伤口发射点随被击中的骨骼移动。鱼身不再画冲击圈。滴血不额外扣血，视觉反馈不移动相机。水面效果使用 `waterSurface` 高度与水域查询。
- `FishDefinition`：60 个有原生模型的钓获目标（含鱼、蟹、鲸与特殊生物），保留原物品 ID；包含普通鱼、攻击鱼、Mini 生物和经过普通钓获适配的 Boss 外观。不是 60 个全部不同的普通鱼种，完整清单见同目录的 `可钓获模型目录.md`。
- `FishDefinition.MaximumHealth`：原有目标为原始 `original.hp` 的 1.5 倍、向上取整；统一倍率为 `FishDefinition.HealthMultiplier`。新增大型 Boss 外观通过 `catchHealthOverride` 设置普通垂钓血量，原始 Boss 数据仍保留；鲸 / 河豚 / 巨型食人鱼 / 蜘蛛蟹分别为 1200 / 750 / 600 / 450。`FishingCatch` 初始化和 UI 使用同一属性。
- `FishDefinition.rarity / catchWeight`：鱼种稀有度和档次内的相对权重。先按本杆水深、距离和事件计算普通 / 少见、稀有、传说的概率，再在对应档次中按拟饵偏好挑选物种。在旧表基础上，少见 / 稀有 / 传说最终概率统一乘 `nonCommonProbabilityMultiplier=0.7`，差额补给普通鱼；基础稀有 14%、传说 3.5% 是两个独立档次；稀有外观另行抽取。
- `FishDefinition.renderVertexCost / renderTriangleCost` 与 `FishingProfile.catchVertexBudget / catchTriangleBudget`：导入时计算普通和稀有外观的较大网格成本。生成器对当前岸边总数进行预算检查，空间充足时所有 60 个目标均可出现；堆积较多时筛除暂时装不下的目标。开始抛竿前至少预留一条普通小鱼的容量；不足时先提示入库，避免抛出后空竿。海马首次保证若因容量不足受阻，本杆用普通小鱼兜底，保证标记保留到空间腾出或事件结束。不会移除现有鱼。演示预算另为场景、海鸥 / 天气视觉和 UI / 弹道预留空间；静态数量估计不等于头显帧率实测。
- `FishingCatch.IsDead / Health / CanGrab`：活鱼不能拾取。枪击可以造成伤害，死亡后停止马达和攻击，才能收获。
- `FishingModule.DisplayCatch / FocusCatch(fish)`：供目标血条读取 / 选择当前鱼；钓获与命中自动切换，已入库或逃走的鱼会被排除。`Demo/FishingDemoHUD` 已接好顶部鱼名、当前 / 最大血量、扣血缓冲条与状态；键鼠为屏幕 UI，VR 为相机前方的世界空间 UI。移植自己的 UI 时绑定该接口即可，或导入 Demo 包复用显示组件。
- `HookedFish`、`KilledFish`、`FishingVitals.Died`、`FishingInventory.Changed`：供其他游戏系统订阅。
- `FishingInventory`：按原物品 ID 汇总不限格数的仓库，数量为 `long`，分别记录原色 / 异色库存。默认示例保存键仍为 `HowToFishPortable.Demo.Inventory.v1`，内部 JSON 为 v2，自动兼容旧库存。目标项目应自行改键，或关闭 `persistence` 并接自己的存档。
- `FishingVitals`：只提供受伤、死亡事件和恢复 API。三秒后返回岸边是演示玩家的处理，核心模块不强制传送自己的角色。

## 每杆咬钩与水深 / 距离收益

一次抛竿实际进入有效水域后，记录最大饵深与离抛竿起点的最大水平距离。入水累计约 2–4 秒即准备好咬钩，收线时上钩；静置时可以继续下沉来选择更深的鱼层。快速收线、鱼饵已从水中拉出或即将收回时，走补偿咬钩路径，在最后有效水中位置连接鱼，避免把鱼生成在玩家身上。每杆至多生成一次，脱钩后不会在同一杆再次生成。向陆地抛竿、主动取消或切走工具不发放钓获物。

- 不足 `minDepth=2` 米：只从 `shallowWaterFish` 标记的 7 种普通小鱼抽取。达到 2 米即开放全部物种。
- `nearRareChance / nearLegendaryChance`：原表为 20% / 5%，全局降低后实际为 14% / 3.5%；`deepRareChance / deepLegendaryChance`：原表深水远投为 25% / 6%，实际为 17.5% / 4.2%；少见档概率也降低 30%，差额回流普通鱼。
- 水深 2–10 米贡献 65% 的收益进度，水平距离 8–28 米贡献 35%；两者分别增加收益，超过范围后不再叠加。使用实际鱼饵位置，不用玩家移动距离充数。
- `maxRareChance / maxLegendaryChance`：原表事件加成后分别封顶 30% / 7%，再乘 0.7 后实际封顶 21% / 4.9%。某档次被容量筛空时，该档次概率回流普通 / 少见，不提高其他稀有档次。
- `CastDepth / CastDistance / BiteReady / CastHasCatch`：供自己的 UI 读取；Demo 已显示当前饵深、最大投距和收线咬钩提示。
- 海马事件的首次保证和后续 50% 海马机会保留为明确的特殊事件规则，不计入普通随机鱼池的档次概率。

## 无限仓库、图鉴与原色 / 异色

`FishingSystem.prefab` 已包含 `FishingArchiveView`，引用 `Definitions/Fish catalogue.asset`、全部静态缩略图、共享剪影 / 灰度材质和中文字体。界面程序集位于 `Interface`，仅引用 Runtime 与 Unity UI；Runtime 继续保持输入与 UI 中立。核心包和演示包都显式包含这些源文件与程序集定义，分文件脚本不会被资源依赖导出遗漏。

- `FishingInventory.Total / Records / Stored(id)`：库存总数、物种记录、指定记录。每条记录的 `count / originalCount / shinyCount` 是 64 位数字，不设置物品格数上限。`Withdraw(id)` 优先消耗原色，`Withdraw(id, shiny)` 指定消耗样式；消耗不会删除永久图鉴记录。
- `Collection / Discovery(id)`：永久发现记录。实际鱼体出水后调用一次 `RecordLifted`；曾出水的活鱼回到水中时记一次 `RecordEscaped`。`FishingCatch` 自动接入这些节点，取消未出水的鱼不会解锁图鉴。
- 成功击败并拾取的鱼调用 `MarkArchiveAcquired()`，按物种与样式永久解锁；入库也会补记。同一实体有防重复标记，反复拾取、放下、再入库不会重复累计收获次数。
- `FishCollectionRecord.Appearance(showShiny)`：未见为 `Silhouette`，仅见过 / 逃走为 `Grayscale`；仅获得异色为 `Shiny`；一旦获得原色默认 `Original`。只有两种都获得才允许按钮切换。后续逃走、取出或消耗不降低解锁状态。
- `FishingControls.OpenCollection / OpenWarehouse / CloseArchive / NextArchivePage / PreviousArchivePage / NextArchiveEntry / PreviousArchiveEntry / ToggleArchiveAppearance`：供自己的 VR 按键或 UnityEvent 绑定，通过库存的 `ArchiveRequested` 传递，不让 Runtime 依赖界面程序集。
- `FishingInventory.ArchiveOpen / ArchiveIsWarehouse`：可供自己的输入系统判断是否阻止走动、抛竿和射击。演示已处理鼠标锁定与恢复、关闭后等待鼠标松开、防止键鼠或 VR 操作穿透。VR 面板不暂停头部跟踪或世界时间。
- 演示：Tab 图鉴、I 仓库、方向键选条目、PgUp / PgDn 翻页、C 切换样式、Esc 关闭；鼠标可直接点击。VR 左手副键打开，左手主键切换页签，左 / 右摇杆分别选择 / 翻页，右手主键切样式、右手副键关闭。已有 XR UI EventSystem 可直接复用；演示键鼠会在缺少 EventSystem 时创建 Input System UI 输入模块。

存档键保持不变，旧 v1 数据升级为 `FishingArchiveData` v2；保留库存数量、拟饵、重量纪录和已消耗的历史物种，并保留旧 JSON 备份。旧版没有原色 / 异色字段，历史条目按原色解锁，不推测异色；升级后的新收获按真实样式保存。界面静态验收使用单独的只读数据，不写入玩家的 PlayerPrefs。

## 海上特殊事件

`FishingSystem.prefab` 已包含 `FishingWorldEvents`，通过 `module.worldEvents` 读取。它的原生海鸥预制体、叫声、海面波纹材质、海马定义都会随核心包导入。事件模型仅在需要时激活；9 只海鸥复用，没有额外物理模拟。摆翼基于原生骨骼，飞行路径为当前版本的适配逻辑。

- 海鸥鱼汛：40 秒内，稀有 / 传说档次概率乘 1.2，再应用 30% / 7% 上限；之后应用全局 0.7 倍降低；异色外观概率现为平时 8%、海鸥期间 24%。
- 海马出没：40 秒内，第一次成功钓获保证海马，其后每次有 50% 独立海马机会。真马使用原始 `Horse` / `HorseDrip` 网格。出水后触发揭晓，不执行额外 Boss 流程。
- `Current / Remaining / Title / Description`：供事件横幅读取。Demo 的顶部 UI 已接入，VR 同样可见。
- `automatic` 默认开启，特殊事件由系统自动随机产生，无需玩家按键或绑定 VR 按钮。
- `firstEventDelayMin / firstEventDelayMax`：首次事件随机等待范围，默认 20–40 秒。`intervalMin / intervalMax`：每次事件结束后的随机等待范围，默认 45–75 秒。`eventDuration`：每次持续时间，默认 40 秒。
- 阵雨鱼潮 / 海雾来客与海鸥、海马并列。阵雨增加咬钩准备速度至 1.75 倍；海雾对两个稀有档次施加 1.1 倍加成，并在各档内部对大体型或攻击型鱼增加 1.35 倍物种权重。两者持续 `weatherDurationMin / weatherDurationMax` 的 90–120 秒，以 `weatherTransition=10` 秒渐入渐出。
- 四种事件的初始权重为 1 / 0.8 / 1 / 0.8（海鸥 / 海马 / 阵雨 / 海雾）；`repeatWeight=.35` 降低刚结束事件的下一轮权重。同一池只抽一个事件，天气不触发其他事件。事件不会重叠，也不与玩家按键绑定；核心包和演示场景使用相同设置。

`FishingWorldEvents.weather` 绑定同模块的 `FishingWeather`。天气临时接管距离雾、环境光、主方向光及玩家相机背景，退出或禁用时恢复进入前的值；目标项目已有天气管理器时应只启用一个环境控制来源。雨丝和雨圈使用固定动态网格，最多 180 条雨丝、12 个水面雨圈、两个无物理的原生装饰鱼；循环雨声与雾风为生成的轻量氛围素材。无体积雾、镜头模糊或雨滴物理碰撞。

打包目标项目时，在 Project Settings → Graphics 的 Shader Stripping / Fog Modes 中使用 Custom 并保留 Linear，确保运行时开启的线性雾变体不被剔除。独立演示项目已设置；核心包不覆盖目标项目的 ProjectSettings。保持 `rainMaterial` 材质引用以携带雨丝着色器。

移植时继续绑定 `module.waterTarget` 至开阔水域参考点，海鸥在海面上方约 9 米处飞过；海马事件的波纹根据该点和玩家方向放置。大型新模型使用单根运动学 / 动态根刚体与统一碰撞盒，避免携带原 Boss 的多刚体控制器。

## 文件边界

`Runtime` 只有玩法和接口；`Interface` 包含可复用图鉴 / 仓库界面；`Demo` 包含可替换的玩家、输入、HUD、简单环境和 URP 配置。核心资源包导出 Runtime / Interface / Definitions / Prefabs / Meshes / Animations / Audio / Materials / Textures / Documentation，不带演示场景或项目设置。

源模型、UV、骨骼、碰撞体、关节、原枪械动画和音效经过静态转换；没有把原游戏的网络程序集或全局单例带入目标工程。

鱼预制体（包括稀有外观）开启了骨骼离屏更新，避免物理关节移动后使用过期边界而消失。最多 12 条未处理鱼的数量限制保留。新增弹头 / 弹道 / 命中圈与粒子为程序生成的适配效果，岸上速度及击退按当前操作要求调整，以上表现与原作参数不再逐项相同。

## 复现边界与验证

按本地 v1.1.1 数据实现普通抛竿、鱼饵下沉和移动触发、权重生成、物理收线、普通攻击鱼、枪械、死亡拾取与入库。当前根据操作要求改为落岸接触脱钩、朝玩家高跳、实际落水逃走，生命值为原值 1.5 倍；不再用离水计时自动脱钩。没有用体力条或反向摆杆小游戏替代这一流程。

完整原游戏的联机、船舶、商店升级、任务推进、主线 Boss 专属阶段和全部特效没有移植。已导入的 Mini 鱼使用其 Fish / AttackingFish 参数；不代表完整 Boss 战。键鼠的抛竿手部动作和 VR 输入采用当前演示适配；VR 保持固定视角，不施加原作镜头后坐力。因此本版本不能称为整款游戏或全部表现的“完全一比一”。

本次只做编辑器编译、资源 / 引用 / 配置和碰撞查询检查，不进入 Play，不调用 Physics.Simulate。实际收线、抛鱼、命中、攻击、死鱼拾取和头显帧率仍需你运行对照。

### 活鱼休眠后的继续跳跃

刚体休眠后 Unity 不再发送持续碰撞回调。FishingCatch 缓存实体碰撞体，在已上岸且近乎静止、近期没有落地回调时，使用碰撞体底部附近的短射线检查实际支撑；尾部支撑也能让已上岸的鱼恢复跳跃。起跳前统一 WakeUp 所有活动鱼段并赋予同一速度。只要生命大于 0 就保留活动；死亡 / 持有 / 挂钩状态仍走原来的分支，不关闭全局休眠，也不增加伤害、跳高或逃跑速度。

### 中文鱼名

FishChineseNames.Get(originalId, fallback) 提供全部 60 个钓获目标的中文名称；所有 FishDefinition 的 displayName 已同步。构建器按固定 ID 应用名称，浅水鱼筛选等逻辑也按 ID 查找。旧库存经 FishingArchiveData.Decode 读取后仅按 ID 转换名称，已有数量、异色与图鉴记录保留。原生资源路径、ID 和存档键不变。
